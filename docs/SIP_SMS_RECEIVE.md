## 原子接收边界

数据库 schema 29 将正常 Inbox、独立来源收据和当时的 SIP 收件计划放进同一个
`BEGIN IMMEDIATE` 写事务。应用在启动实时 IMS 接收器前安装纯 planner；
`Manager.New` 也为实际 Store 安装同一 planner。planner 只读取事务内的 Inbox、
持久 SIP 设置及私有日志快照，不使用某个 Manager 的旧内存配置，不执行网络操作。
只有事务提交成功后才发出入库唤醒，后续 worker 不再按轮询时的新账号重建计划。

实时 Host IMS／VoWiFi 收件的 `SaveSMSMessage` 进入 `SaveSMSMessageWithResult`；历史／手动同步走
`SaveSMSMessageArchiveWithResult`，批量历史导入同样归档。正常 Inbox 仍保存短信，
“归档”只表示不能据此给 SIP 收件人建立新计划，不是丢弃原文。

第一次具备完整、可解码内容的实时拼接短信才捕获一次逻辑计划。尚不完整的实时分段
不提前占用该逻辑来源的空收据；已按历史归档的分段则不能靠随后补齐升级成实时消息。
USSD 不作为手机短信转发。

以下“不补发”受后文的来源保护期限约束，不表示永久防重。

| 保存时状态 | 原 Inbox 与来源保护 | 以后改变设置 |
| --- | --- | --- |
| 已开启且有原接收授权 | 保存原收件人、身份代际及内容绑定 | 不追加新分机；原授权撤销可阻止投递 |
| SIP／手机短信关闭，或没有接收授权 | 保存 Inbox 和空计划来源收据 | 开启、加账号、改默认线路均不补发 |
| 历史导入、手动同步或来源已归档 | 保存 Inbox 和空计划来源收据 | 不转成新短信、不为新账号补发 |
| 私有转发队列达到容量 | 保留 Inbox 和空计划来源收据 | 释放一个位置后重送同来源也不补发 |
| 来源收据容量达到上限 | 保留 Inbox，持久化保护窗口，暂停新计划 | 释放容量不立即解除保护 |
| 需要读取的私有设置／日志损坏、持久提交失败 | 整个接收事务失败 | 不静默改走内存发送；修复后才能重新保存 |

空计划不是一条含正文的待发记录，而是独立来源收据。明确的转发容量不足与数据库
故障不同：前者允许本地收件成功，后者回滚 Inbox／收据／计划，不能部分提交。
未安装 planner 也只形成空计划，不在之后安装时扫描历史补发。

## 来源身份、升级与保留期限

`sms_forward_receipts` 保存来源摘要、指纹和期限；`sms_forward_receipt_state` 保存
初始化状态及容量保护期限。来源键绑定已保存的物理模组标识、原 ICCID 和稳定消息 ID，
缺少消息 ID 时只退化到该 Inbox 行 ID，不从当前插着的卡补身份。

原发件人和原 ICCID 在 Inbox 规范化前捕获，写入私有来源元数据；后续覆盖、拼接及
调用者提供的 Extra 不能改写第一次的来源归属。未知卡不会因为之后读到当前 SIM 而
获得可付费回复地址。内容指纹还绑定实际 Inbox 的设备／卡、消息 ID、发件人、正文、
方向、可投递状态和原来源元数据；本地已读标记和更新时间不参与指纹。
已有 Inbox 的硬件身份补全或消息来源 ID 编辑，也不是新的网络到达证据；若因此改变
来源键，本次只保存新的空来源收据，不按当前账号再建第二份计划，原计划的旧指纹仍须核验。

首次升级到 schema 29 时，在同一写事务为已有收件箱登记空来源收据，只读已保存的
来源字段，不读旧正文、不猜当前 SIM、不创建转发计划。二十四小时从迁移时起算；
已有初始化标记的重启不重扫或续期。旧记录没有原来源元数据时视为历史未知来源，
不能通过补字段恢复实时资格。升级前已删除的来源无法凭空恢复。

来源收据最多 32,768 项，保留二十四小时，重复来源不延长原期限。容量满时，最后一个
未能登记的来源会延长持久保护窗口到当时之后二十四小时；窗口内新收件仍能入库，
但不建立新计划。过期清理前先验证记录和保护元数据，损坏不能当成空表。
私有日志最多 256 条逻辑 MT 记录、每条 16 个接收人、总日志 4 MiB；终态和 Unknown
也占容量。原 Inbox 不因转发记录过期而删除。

启动时在同一写事务幂等补建无效行部分索引和过期索引，已是 schema 29 的旧库也会补建。
逐次收件仍先检查完整来源元数据和无效行、再清理到期项；普通直接 SQL 修改同样维护
索引。查询没有强制索引：缺失时退回完整校验，不把“找不到索引”当成空历史。
这项优化避免批量收件反复对每行执行结构匹配，不代表任意数据库文件物理损坏都可检出。

这些是基于系统 UTC 的有界防重。来源缺少稳定 ID、时钟跳变、过期后重送、删除数据库
或恢复旧备份，均不能承诺无限期识别原消息，也不是运营商层的 exactly-once。

## 实际 Inbox guard 与独立库 API

应用捕获的计划保存真实 `InboxID`、`SourceKey`、`SourceFingerprint`，且
`SourceIndependent=false`。claim 以整记录 CAS 把原接收人写成 Unknown，并在同一个
写事务再次检查实际 Inbox 行；删除、修改正文／方向或其他绑定字段会取消仍未尝试的
原计划，不发送旧拷贝。仅标为已读不取消投递。

后续[逐包核验阶段](../../publish/vocat-sms-wire-20261024/README.md)已将 MT 投递改为独立的
有界 UDP 事务。初发、T1/T2 重传和 401／407 后认证发包都重新读取一个真实 SQLite
只读快照：当前私有设置、日志以及实际 Inbox 必须来自同一读事务。日志仍须有原
接收人身份、Unknown、attempt token、期限、来源和载荷（含固定回复目标）。明确的
`SourceIndependent` 只豁免 Inbox 查找，不豁免原 claim、身份、权限和载荷核验。
独立库宿主未实现 `ReadSMSForwardWireSnapshot` 时不能发送，不能用恒定 true 代替。

快照读取不建表、不续期、不修复历史或写状态；取消、读取或清理异常不返回部分授权。
最后一次数据库等待后只做同步 Contact／关闭／期限核验，不再插入另一数据库等待。
数据库等待期间到达的合法最终响应优先于重传或后来 veto；1xx 不会挤掉最终响应，
也不重置原总期限。认证换 branch 与 CSeq，并先退役旧事务。
仅 MT 使用该路径，普通分机 MESSAGE、REGISTER 和通话保留原来的 sipgo 路径。

原账号删除重建、凭据代际重置、线路收件授权撤销不能凭旧 runtime 继续投递。
正常关闭暂停原 Queued；claim 后未得到接受结果的尝试保持 Unknown，不自动复活。
检查与远端网络不是原子提交，已发载荷不能撤回，也不能阻止最后核验后的瞬时变化。
总期限限制核验／重传／认证等待，不承诺强行中断已进入操作系统的阻塞 UDP 写；
不会为此改共享 socket 的 deadline 而干扰 REGISTER 或通话。

库 API `Manager.QueueSMS` 仍允许宿主显式提交不依赖 Inbox 的事件，标记为
`SourceIndependent=true`。它不具备实际 Inbox 删除／编辑 guard，不能据此宣称所有库
宿主都有应用收件事务的保证。应用不再用旧 Inbox 轮询把普通短信转换成该独立事件。
`SMSCursor` 只保留兼容／升级用途：旧日志中既没有 Inbox 绑定、也未明确独立准入的
Queued 保守取消为 403；原 Unknown 保持未知，不借升级重放。

## AT 模组存储的保守观察

AT 存储扫描不能证明一条短信刚从网络到达。当前以进程内的完整 scope 建立观察基线：
物理设备、IMEI、ICCID、IMSI 和 IMS 模式都参与资格，读取前后身份须稳定。
进程第一次完整成功扫描、scope 切换后的第一次扫描，以及手动同步都按历史归档。
之后同一完整 scope 的 observed 扫描才允许新出现的物理 PDU 行形成实时逻辑消息；
槽位／PDU 的摘要只用于观察，不把存储槽位本身当永久网络消息 ID。

在归档扫描中首次遇到的不完整拼接 family 保护二十四小时，按首见时间到期，重复扫描
不续期；scope 变化也保留尚未到期的 family 哈希，身份未知时使用保守 `guardUntil`。
family 绑定 scope、发件人、分片引用和总片数；同一组合在保护期内被真正复用，也可能
保守地不转发，完整本地收件仍保留。每配置最多 4,096 个行／family 摘要，全局最多
16,384 个、512 个配置范围。
这些资格只保存有界摘要，不保存正文／原始 PDU。当保护证据因预算溢出、淘汰或遗忘
而丢失时，本进程余下时间采用 archive-only，不会等二十四小时后假定已恢复可信观察。
此降级只影响 SIP 转发计划，正常 Inbox 保存和原始 PDU 归档仍继续。

因此首次扫描可能把真正刚到的短信仅保存在本地收件箱；重新启动也重新建立归档基线。
这是避免把旧存储短信转给新账号的保守权衡，不是网络到达证明，也不是无损实时转发承诺。

## 紧凑原卡回复地址

可回复的 From user-part 为
`sms2-<设备摘要12位hex>-<原ICCID摘要43位base64url>-<国际号码>`，最长 78 个 ASCII
字节，避开本项目已观察到的 Asterisk 79 字符字段边界。卡摘要仍完整保留 SHA-256，
不把缩短地址当作授权。设备摘要按 Go 精确大小写计算，解析只允许唯一匹配的配置设备；
零个或多个匹配都拒绝。原 ICCID 必须为 18–22 位 ASCII 数字，可回复号码必须满足
严格国际号码格式；未知卡／不合格式的来源使用只读地址。

兼容完整旧格式 `sms.<设备base64url>.<原卡64位hex摘要>.<号码>`，但不会修补截断、
不规范编码或残缺字段；恰为已知 79 字符边界的旧格式保守拒绝。新旧短信命名空间即使解析失败也不进入普通号码／默认线路，
换卡和原线路权限变化仍须重新检查。软电话仍需配置实际出站代理，统一身份域不是路由。

格式校验不能识别所有截短：若号码尾部被删后恰好仍是另一个合法长度的号码，地址没有
号码完整性签名可据此识别。78 字节解决已知长度风险，不等于任意链路截断检测。
本阶段尚未新增真实 Asterisk／运营商互通验收。

私有日志现为 v3。原子计划同时保存 `canonical_reply`：严格国际号码原样保留；国内
号码只按首次接收事务中的明确国家码和精确国内位数补全一次。显示名仍为原始发件人。
显式 `QueueSMS` 也只使用第一次准入的配置；重复事件、CAS 竞争、换 Manager 或之后
修改国家码均不重新解释原号码。该目标纳入 claim、取消及完成的载荷指纹，旧最终响应
不能完成一个已更换目标的新载荷。空字符串表示明确只读，不在以后补猜。

v1／v2 升级只为原始严格 `+E.164` 发件人保留可回复目标；旧国内号码、短码及字母
来源保守只读，不按当前配置补国家码。v3 缺失／null／畸形字段失败关闭；旧二进制因
不支持 v3 而拒绝该日志，不能忽略新字段后继续重解释。v1 原 token 迁移规则不扩大到
v2，Unknown、原期限和游标也不借这次升级复活或重置。

## 固定 peer 的离线探测

固定中继不靠 REGISTER 表示在线。投递前先核对当前持久授权，再向运行实例固定的端点
发送中性 `keepalive`／`gateway` OPTIONS；不携带正文、手机号码、SIM 摘要、回复别名或
Authorization。精确匹配来源、Via、Call-ID、CSeq／方法、From／To 的 200，或符合固定
Realm、允许算法及可用 qop 的 401／407，才视为对端可达；探测不计算或发送 Digest 证明。
1xx 不续期，错误来源／身份、过期或停止后的最终响应不能建立成功结果。

每个不可变运行实例最多一个共享探测 owner，最长一秒；正／负结果分别短存一秒，读取
不续期，重启或配置替换不继承。单个等待者取消不取消其他等待者的 owner；实例关闭
取消并等待自己的 owner。等待期间不持服务／运行时锁或数据库事务。

未可达时原目标保持 Queued、空 attempt token、原期限及来源，不续期或扩大计划。
探测成功后，claim 仍重新核对当前持久授权、原身份、原期限和实际 Inbox；撤权或改源
不能借成功探测发送旧内容。只有原 Queued 的 durable claim 成功后才允许正文。
探测、数据库操作、正文、认证和重传共用原总预算；预算直接继承调用者取消。
每轮最多 16 个接收人，本地注册分机优先，同一固定端点最多一个 peer 投递 worker，
多个别名不能占满本地工作槽。原 Unknown 不恢复为 Queued，也不自动重发。

这只证明固定对端短时可达，不证明 MESSAGE 权限、PBX 后分机在线、终端展示或已读。
普通分机 MESSAGE、REGISTER、语音路径及通用 peer 状态不接入该短信专用探测。

## 仍有的传输边界

MT 文本准入现为非空、无 NUL、严格 UTF-8，最多 16,384 个 UTF-16 单元；补充平面
字符占两个单元。原文按 Unicode scalar 边界分块，每块最多 280 个 UTF-8 字节；
多块添加可见 `[i/n] ` 编号，单块原文不变。编号不占原文的 280 字节，但包含编号、
全部头部和认证的每个完整 UDP MESSAGE 仍不得超过 1,300 字节，长 Contact／认证头
可能使其安全拒绝。固定样例见[共享分段契约](../../contracts/sip-message-parts-v1.json)。

每个 Contact 顺序发送全部分段，每段独立事务、至多一次 peer 认证重试；原 claim、
attempt token、来源、canonical 回复目标及逐包检查不变。探测、所有分段与认证共用
原调用者预算（Go 默认五秒），不逐片重置。至少一个 Contact 必须完整接受全部分段，
不能把不同 Contact 接受的不同片拼成成功；一份完整副本全 200 才返回 200，含 202
则返回 202。首段尚无 2xx 时保留底层失败分类，原超时仍为 504；一旦本 Contact 已接受
任一分段，后来拒绝、改源、撤权、取消或不确定均转为 504 Unknown，不自动续发／重投。
首段拒绝也不是正文从未进入网络的证明。

这不是任意长度、字素簇／CRLF 不拆、运营商 UDH、软电话透明重组或已读保证；不改变
普通分机 MESSAGE／运营商 MO 的 4,096 字节准入。私有日志仍为 v3，4 MiB、256 条
逻辑短信及每条 16 个接收人上限不变。旧 v3 程序可能拒绝新范围内的较长记录，不能
承诺无损降级读取。

Go 仍限可信内网／VPN、UDP、UTF-8 `text/plain`，不截断正文冒充成功。
本地分机没有有效注册时等待；固定 peer 探测失败也保留尚未认领的原 Queued。
任一 Contact 完整返回 200／202 只表示该接收人接受，不保证所有终端展示、PBX 后分机收齐
或用户已读。Unknown 不自动重投。私有标记和摘要不是磁盘加密，数据库仍需访问保护。
