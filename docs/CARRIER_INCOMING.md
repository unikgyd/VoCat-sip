# 可选模组 IMS 入呼 → SIP 分机群振

设备所选且已注册的 VoWiFi 或 [Host IMS](HOST_IMS_APPLICATION.md) 现在可将新来电送给
选定分机，与 HTTP／Telegram 接听接口共享接听权。[网页电话](WEB_PHONE.md)随后已接入
跨页来电卡片、接听／挂断和浏览器音频交互，与 SIP 分机共用首接仲裁；软件与合成 PCM
已验证，不能据此宣称真实麦克风听感或跨端联合验收通过。
这是 [IMS 外呼桥](CARRIER_OUTGOING.md) 的入呼补齐，不包含 Linux USB 双向音频桥或
[Asterisk 固定中继](ASTERISK_RELAY_PLAN.md)。实现独立编写，参考现有 VoSharp 的来电分叉／首接取消设计；
原 LICENSE、地域、设备、SIM 及其他授权控制不变。尚未进行真实运营商听感验收。

## 配置

在「设置 → SIP 分机服务」开启服务、分机通话及「模组通话桥接」。每条线路另有：

- `allow_incoming`：默认 false，对应「来电通知分机」。与 `allow_outgoing` 独立。
- `incoming_extensions`：默认空数组，填写自己的已配置分机号，最多 16 个；
  分机还需开启 `allow_calls`，没有“默认通知所有账号”的隐式权限。
- 线路不开入呼或未选择分机时，保留原有接听接口与通知渠道行为；不回答、不挂断来电。

示意片段（非内置配置）：

```json
{
  "device_id": "your-configured-device-id",
  "allow_incoming": true,
  "incoming_extensions": ["your-extension-number"]
}
```

示意中的字符串需替换为真实配置：分机号必须是 2–12 位数字。保存配置不会读 SIM、
注册 IMS 或拨打电话；启用不追溯转接此前已经响铃的来电。改号／删除分机时，UI 清除
旧号的入呼授权，不自动授权新号；旧版本配置缺少这两个字段时继续关闭。

## 实际处理

1. 现有 IMS 来电回调先把设备 ID 和原 Call-ID 交给网关，然后照常发送既有通知。
   网关异步核对实体模组、当前验证过的 SIM、已注册 IMS、现有策略和**那一通**入呼；
   不信任回调中的显示号码来选择模块，也不借用 HTTP 的 AT 回退路径。
2. 只通知获准、在线且未占用的分机。每账号多个 Contact 按实际 UDP 来源去重，
   不信任 Contact/Via 主机；每组最多 64 条腿，超额整组不接管，不随机漏掉终端。
3. 各腿独立 Call-ID／标签和 RTP。首个合法 200 被 ACK 后尝试取得 IMS 接听权；
   其他腿取消，迟到 200 一律 ACK 后 BYE，不能把第二个接听者接到已有通话。
4. HTTP 或 Telegram 接听先取得同一个本地接听权，立即取消 SIP 振铃；延迟送达的
   来电回调也被隔离。IMS 自身仍执行原子的单接听者检查。若发现本地已经接通，
   无论此时是否排队到达 SIP 200，都取消 SIP 腿，绝不因此挂断本地已接通的电话。
5. SIP 首接后，从 IMS 取得 8 kHz 单声道 PCM，与获胜腿的 PCMA／PCMU RTP 双向桥接。
   不使用主机麦克风／扬声器，也不允许网页音频 WebSocket 抢读 SIP 拥有的 PCM。
   既有管理 API 仍可查询实际 IMS 通话状态、执行整通挂断。
6. SIP 端 BYE、运营商结束、媒体失败和关闭 SIP 服务都清理对应腿；SIP 拥有的
   已接听呼叫在后台有界结束。关闭不注销整条 IMS、不切换模式、不等待模组恢复。
   若只是网页已接管、分机全忙／离线／超时，不挂断独立的本地来电。

普通 4xx／5xx 只结束对应分机尝试；组内无人接听仍可用管理 API 或 Telegram 接听。
未产生获胜者时分机全局 6xx 拒绝会结束整通来电。管理端挂断接口仍结束整通，不是仅本机静音。
默认群振上限 30 秒，SIP 先接后的 IMS 接听／媒体建立另限 10 秒。每模组一条线路租约，
互不占用另一个模组；获胜后释放其他账号的群振占用。

重复入呼事件以设备 ID＋Call-ID 的哈希记忆，管理器内保留 24 小时、最多 2048 条。
不是跨进程或重启后的接听恢复数据库；活动呼叫也不做跨进程迁移。不能启动多个
网关管理器争抢同一模组。底层不响应取消时，SIP UI／监听器仍可退出，对应旧租约
保留到后台精确清理完成；不会以超时为由换卡或重拨。

## 状态与验证范围

`carrier_outgoing`／`carrier_incoming` 表示已启用的实现能力，`carrier_bridge` 表示二者
均可用，不证明任何 SIM 已注册或 AMR 编码已装好。只有已接线的后端才报告入呼能力。
通话状态提供 `transport: carrier_incoming`、模块 ID、阶段和获胜分机；包数不代表听感。

真实回环 SIP／RTP 加合成 IMS 后端覆盖多账号群振、迟到 200、网页抢接、回调延迟、
双向 PCM、来显、双方挂断、忙线／拒绝／超时、两模组并行和受阻 IMS 接听时快速退出。
独立回归先复现了「已观察到网页接通、SIP 200 又入队」时的误挂断，再验证修复。
界面用隔离 API 预览检查中英双语、桌面／窄屏、保存恢复、失败保留草稿和新线默认关闭。

Linux 测试只部署到用户指定的 `root@10.0.0.2` 隔离目录，不使用 WSL，不安装服务，
不读真实 SIM，不写现有 Asterisk 配置，也不在宿主网络空间启用 XFRM/TUN 实验。
记录见工作区 `publish/vocat-carrier-incoming-20261023/`。

默认静态构建仍未启用原生 AMR-NB；必须按 [AMR_MEDIA](AMR_MEDIA.md) 准备对应后端。
后续已接入[网页电话](WEB_PHONE.md)的跨页提醒、接听／挂断、独占音频与 AudioWorklet PCM，
仍需真实浏览器音频及软电话联合验收。手机短信桥已在[独立阶段](CARRIER_SMS.md)接入合成链路。
后续已补 [RFC 4733 DTMF 跨腿](SIP_DTMF.md)及显式 [USB 模组媒体](MODULE_VOICE.md)。
AMR-WB 编码、RTCP、SIP INFO DTMF、保持／重协商、TLS/SRTP、公网 SBC 和真实
双模组／软电话／运营商联合验收仍不完整。单独映射 SIP 端口不提供可用公网语音。
