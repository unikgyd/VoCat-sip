## 提交与尝试归属

`sip.gateway.sms-ledger.private.v1` 是私有整记录日志，键名不变、格式现为 v3。
`CompareSMSLedger` 比较读取时的精确原始字节及 Sensitive 标志，不使用普通 Upsert
覆盖较新版本。冲突后重读并重新执行纯状态变更；CAS 内不能执行网络或运营商发送。
只有已确认写入的占位获胜者才能继续，存储不可用、提交异常及容量不足均拒绝发送。

日志要求实际文件数据库与持久 journal。每次物理建连先设置并读回外键、5 秒 busy
timeout、WAL 和至少 FULL synchronous，失败不把连接交给池。私有 CAS 在同一连接上
验证持久条件并提交；失败 COMMIT 后清理原事务，无法确认则丢弃物理连接，后续建连
仍经过完整初始化。内存库可用于普通 Store，但不能授权持久短信或 SIP 设置 CAS。

收费发送及每个 MT 接收人的尝试都先提交 Unknown（504）与独立随机 token。
完成只能更新仍匹配原 payload／身份和 token 的 Unknown；过期后同 ID 新尝试不被
迟到 worker 覆盖。停止、取消或结果不确定不把 Unknown 改回排队，不自动重发。
MO 的设备级运行期隔离锁在更换监听器后仍保留，卡住的旧后端不让该模组重复提交。

v1 升级先验证原记录，以 CAS 保存当前格式，并给原有尝试分配 token；不借升级重发原
Unknown，已有接受／未知结果及期限保留。另对旧 MT Queued 做来源隔离：没有实际
Inbox 绑定、也未明确标记 `SourceIndependent` 的旧轮询记录保守取消为 403，不猜测其
来源还存在或身份仍安全。原 Unknown 不因这种隔离变回 Queued。
v2／v3 缺失／损坏 token 或非法日志失败关闭，不清空历史重建空日志。
v3 将接收时确定的 canonical 回复目标纳入载荷指纹；v1／v2 只保留严格国际原发件人的
可回复目标，其余保守只读，不按当前国家码重解释。v3 缺失该字段不是空只读决定，
而是损坏历史。旧二进制拒绝新格式；升级不重置 Unknown、原期限或游标。
日志上限 4 MiB、
2048 个收费尝试、256 个 MT 记录，保留窗口 24 小时；这些是有界防重，不是无限期或
运营商恰好一次保证。

## 原子 Inbox、空计划与来源收据

schema 29 的真实收件不再先入库、后按轮询时配置调用 `QueueSMS`。同一个
`BEGIN IMMEDIATE` 事务保存实际 Inbox、原始来源元数据、独立来源收据及当时的私有
收件计划；成功提交后才唤醒 worker。planner 使用事务内持久配置，不捕获旧 Manager
内存状态，也不在持锁期间执行网络或运营商操作。

手机短信开关关闭、没有接收授权、历史导入／手动归档、未安装 planner，或明确的转发
容量不足，都保留本地 Inbox 与空来源保护；来源保护期内，之后开启、新建账号或腾出
容量不补发原来源。
正常实时拼接则等第一次完整可解码后才捕获逻辑计划，避免用未完成分段提前建立空收据。
需要读取的私有设置／日志损坏、来源保护损坏或提交失败会回滚整个接收事务，不能降级
为直接内存发送。转发容量满与存储错误不是同一个失败类别。

来源收据最多 32,768 项，期限二十四小时，重复事件不续期，删除 Inbox 不删除独立收据。
容量满时持久保存保护窗口；窗口内 Inbox 继续保存，释放少量容量也不立即建立新计划。
首次升级只用旧 Inbox 已保存的来源字段登记空收据，期限从迁移时起算，不读取旧正文、
不推断当前 SIM；初始化完成后重启不重扫或续期。原先已删除的来源无法恢复，缺少稳定
消息 ID 时只具备原行 ID 范围的保护。
同一启动写事务幂等补建无效行及过期索引，兼容已有 schema 29 库；结构校验仍覆盖
直接 SQL 写入，且先于到期清理。缺失索引会安全退回完整查询，不跳过历史校验。

应用计划绑定真实 `InboxID`、`SourceKey`、`SourceFingerprint`。claim 的 Unknown CAS
与实际行存在／内容检查同事务；每次 MT UDP 初发、认证及超时重传前还检查实际行。删除或修改正文、
方向等绑定字段会阻止旧内容投递，标为已读不影响指纹。claim 前确认来源已变更时取消原 Queued，
claim 后不确定则保持 Unknown，无法撤回已交给网络的消息。

库宿主显式调用 `QueueSMS` 时仍可建立 `SourceIndependent=true` 事件；它不依赖实际
Inbox，因而不具备上述删除／编辑 guard。应用的实际 Inbox 不再通过这个兼容入口补投。
更完整的来源、AT 保守观察及升级规则见[接收入库与原计划](SIP_SMS_RECEIVE.md)。
发送时 Settings／Ledger／实际 Inbox 使用一个只读快照，并重新证明仍拥有原 Unknown
claim；随后仅同步检查 Contact／停止／期限。具体代码与独立验证状态见
[逐包核验阶段](../../publish/vocat-sms-wire-20261024/README.md)，不扩大前一阶段的验收声明。

## 接收身份与即时撤权

本地账号身份绑定 Realm、分机、凭据及私有随机 epoch。同密码重新填写、显式重置、
删除重建、Realm 变化会轮换；普通保存、关闭再开启及重启保留。同名新账号不能接手
已经按旧 epoch 排队的短信。设置页将重置放在高级项，说明不改密码，仅重置接收身份。
私有 epoch 不从公开 API 导出，`reset_credential_identity` 是一次性指令。

Manager 启动先持久迁移／确认身份，保存使用独立 revision 和精确原文 CAS。
即使配置内容再次变回相同值，revision 也防止旧回滚覆盖较新的保存。监听失败只回滚
仍由自己拥有的候选版本，不能确认就保持停止，而不是强行恢复旧配置。

真实 Manager 的 MO 准入、MT claim、每次 MT UDP 初发／重传及 Digest 重试读取当前持久授权。
另一个 Manager 只刷新 revision、未改变身份和权限时，旧运行实例仍可正常工作；
身份重置或线路授权撤销后不能依赖旧内存快照继续操作。claim 后被 guard 阻止、且未有
接受结果的尝试保持 Unknown，不声称能撤回已交给网络的载荷。MT 还核对当前实际
注册来源及 Contact，不使用退休绑定。

## 成功定义与剩余边界

MO 202 是传输层接受，不是手机收件或已读。MT 多 Contact 中任一完整接受全部分段才算该分机接受，
不是全部终端收齐，不补发给以后注册的同账号设备。日志正文依赖数据库权限保护，
Sensitive 不是磁盘加密。仍仅可信 LAN／VPN、UDP text/plain，遵守整包 1300 字节边界。

MT 的[显式 MESSAGE 分段](SIP_SMS_RECEIVE.md#仍有的传输边界)使用共享 280 字节原文块及
16,384 UTF-16 单元准入，单条逻辑计划仍只认领一次，不为分段建立新期限或可重放子任务。
同一 Contact 已有分段被接受后，后来失败保持 Unknown，不能拼接其他 Contact 的部分成功。
日志仍为 v3、4 MiB／256 条逻辑 MT／每条 16 个接收人；升级未扩大容量或重置防重。
较长的新 v3 记录可能被旧 v3 二进制拒绝，不承诺降级兼容。最终软件验收状态见
[分段阶段记录](../../publish/vocat-sms-parts-20261024/README.md)。

可回复地址已采用最长 78 个 ASCII 字节的 `sms2-` 格式，保留完整原卡 SHA-256，避开
已观察的 Asterisk 79 字符字段边界；完整旧格式可兼容，恰为 79 字符的旧地址保守拒绝，残缺／非法格式失败关闭，
不落到默认线路。若号码被截短后仍是合法号码，格式校验不能识别这一点，不能把长度
优化说成任意链路截断检测。本轮尚未新增真实 PBX／运营商互通验收。

仍有以下边界：

- AT 存储扫描是保守观察，不证明网络到达。每进程／完整 scope 首次扫描归档，之后
  observed 新物理 PDU 才可能实时转发；首次真正新短信可能仅进入本地 Inbox。
- 归档不完整拼接 family 从首见保护二十四小时、不续期；失去保护证据或超出观察预算
  后本进程 archive-only，不假定到期自动恢复，正常 Inbox 不受该转发降级影响。
- 固定 peer 在 claim 前使用独立无正文 OPTIONS；探测失败保留原 Queued／期限，成功
  仍须重查当前授权与原实际 Inbox。探测、claim、认证和正文共享总时限，不重置预算。
  只有未认领的目标可继续等候，原 Unknown 不自动重试；探测不证明下游终端收件。
- 显式编号分段不等于任意长度、透明重组或所有终端收齐；实卡、真实长消息、跨网络
  软电话、送达报告及生产部署需独立验收。
- 系统时钟跳变、过期、删除／替换数据库或恢复旧备份不能据此获得无限期防重保证。

不使用 WSL；当前实现说明及合成验证均不能代替真实运营商短信验收。
