# 分机 MESSAGE（不含手机短信）

VoCat 的可选 SIP 服务已接入分机间 UTF-8 纯文本消息，可与分机注册功能独立开关。
本页描述内部消息，不经过模组、SIM 或 Asterisk。另已接入默认关闭的
[手机短信桥接](CARRIER_SMS.md)，其授权、持久化防重和收件队列独立。
现阶段仍限可信内网／VPN、UDP，不宣称公网、TLS、CPIM 或群聊支持。

## 启用与权限

在设置的「SIP 分机服务」卡片：添加并注册分机后，开启「分机文本消息」，并为需要
收发的账号开启「收发分机消息」，最后保存。全局开关和两个账号的权限必须同时允许。
新安装及旧注册配置升级均默认不允许消息；没有预置账号或密码，不因升级自动转发。
保存变更会重建 SIP 运行时，终端须重新注册。内部消息与手机短信权限分离。

只发送给配置中已存在且在线的分机。未配置分机返回 404，离线返回 480，权限关闭
返回 403。上述未知目标行为以手机短信桥接关闭为前提；开启后只有独立授权的手机号码
才进入指定 IMS，已知分机不会被当成外线，不存在 AT 或 Asterisk 兜底。Content-Type 支持 text/plain，
UTF-8、US-ASCII（校验实际字节），不支持 HTML／CPIM／压缩正文。无 charset 时按
兼容策略接收有效 UTF-8，转发始终明确标注 UTF-8。

## 跨网段身份和实际地址

接收请求时按已鉴权分机号确认发件人，不信任来件显示名称或 P-Asserted-Identity。
按 Request-URI 的用户部分查找收件分机，域名不同不会加国家码或转为手机号。转发
重新生成 From／To，显示名称来自配置，不复制来件授权、Route、Reply-To 或身份声明。

高级设置可填写「统一身份域」（DNS 名或不带方括号的 IP，无端口／sip:），留空使用
Realm。它是消息地址身份，不是实际发送目标；改变它不需要更换密码。所有软电话仍
应设置指向同一 SIP 服务的出站代理。服务端能忽略收件地址的域名来查分机，但无法
强迫某个客户端把回复发到服务器，不能声称随意的 @地址 在所有客户端都无影响。

实际投递只使用注册时观察到的 UDP 来源 IP／端口，并复用 SIP 监听套接字；不会访问
Contact 或 Route 中任意主机。保留 Contact 的 URI 用户部分供终端识别。一个账号
最多八个 Contact，向多个在线来源并行投递；同一来源的多个别名只投递一次，使用
递增注册序号选取最新 Contact，不依赖可能精度不足的墙钟时间。

## 回执、重试和退出

只有收到匹配的终端最终响应才报告结果：至少一端 200 时返回 200；只有其他 2xx
接受响应时返回 202。都不代表用户已阅读，也不保证同账号所有终端已收到。没有确认
且有超时／传输不确定性则返回 504、X-VoCat-Delivery: unknown，不提前回成功。
全部明确拒绝则返回相应失败分类；3xx 不自动重定向，401／407 不向终端泄露其他凭据。

响应在进入 SIP 事务状态机前校验实际来源、Via 分支、Call-ID、CSeq、From／To 身份和
From 标签。重复 From／标签、错误大小写或不相干响应不能把消息变为成功。双方共享
九条不透明响应身份契约；Windows 网关也同步补强 From 标签、Call-ID 大小写和重复头。

同分机、Call-ID、CSeq 组成业务请求身份，独立于 Via 分支和 LAN／VPN 域名。五分钟
内相同内容返回原结果，不重新投递；换正文或收件人返回冲突。结果未知也不新开事务
自动重投。UDP 同一事务的标准重传仍存在，接收端须按 SIP 事务去重。当前去重仅在
运行时内存中，重启后不保留，不能用来声称已实现运营商收费请求的持久化防重。

每个收件分机同时最多一批投递，全局最多 32 批，结果缓存最多 2048 条。忙时明确
返回 503，而不是积累无限队列。每批默认五秒截止；退出先取消所有网络任务，再
关闭本地事务及套接字，不等待远端超时或模组恢复。不记录／导出消息正文。

按 [RFC 3428 第 8 节](https://www.rfc-editor.org/rfc/rfc3428.html#section-8)，没有正向
路径 MTU／拥塞安全保证时，外发 MESSAGE 整包不得超过 1300 字节。当前超出返回 513，
不截断文字、不偷偷转手机短信；4096 字节是输入资源上限，不是可发送的 UDP 正文额度。
大消息／其他传输及真实软电话、Asterisk 联合验收仍是后续工作。
