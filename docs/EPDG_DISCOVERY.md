## 设备页配置

设备概览下展开「高级 · ePDG 发现」。未识别 SIM 时不能保存；配置按 ICCID 保存，
同一窗口的其他模组／卡不受影响。修改只在下一次连接生效，不自动重连、切换射频或
改变已有通话。API 会校验本次读取配置对应的 SIM 指纹，换卡后的旧表单返回 409。
指纹仅用于防止误写，不替代管理员登录和 CSRF。

- 优先地址：域名、IPv4 或 IPv6，每行一个；不含 URL、端口、路径或凭据，最多 16 个。
- 补充 PLMN：`MCC-MNC` 或五／六位数字，最多 16 个。实时预览标准域名，例如
  `515-66` → `epdg.epc.mnc066.mcc515.pub.3gppnetwork.org`、
  `204-04` → `epdg.epc.mnc004.mcc204.pub.3gppnetwork.org`。MNC 补足三位，不改认证身份。
- 仅手动地址：不添加自动候选，也不恢复已从手动列表删除的历史地址。
- 公共地域 DNS 回退：**默认关闭**。只有显式开启且系统 DNS 无可用地址时，才使用
  既有 Google DNS-over-HTTPS 地域兼容查询；支持 A／AAAA，不发送 IMSI、ICCID 或 AKA
  数据。会向该公共服务发送 ePDG 域名及既有地域查询提示，请按自己的网络政策决定。

「恢复自动发现」先修改表单，仍需保存；清除手动选项和公共 DNS 开关，但保留成功
记忆。折叠面板、刷新设备状态不会主动清掉当前草稿；换卡会重建表单。

运行状态显示当前／正在尝试／最近尝试的域名；隧道建立后显示实际选中的 IP。失败
后保留域名不代表仍在线。详细状态中的 epdg_attempt／epdg_candidates 统计“域名＋认证归属”
尝试组合，不是逐 IP 次数；不能拿解析成功或拿到 IP 当作 IKE／IMS 注册成功。

## 候选与认证边界

优先顺序为匹配当前卡和认证归属的历史成功域名、手动地址、已有端点／运营商配置、
SIM 已知归属，再到补充发现 PLMN／发卡信息提示。去重后最多 64 个端点／归属组合。
只改变连接目的地，不凭发现 PLMN 构造新 IMSI，也不根据发卡国家改写认证归属。

现有显式运营商身份兼容配置是另一层策略，并未删除。针对带订阅身份重写的配置，
本轮收紧了 IMSI／ICCID 约束：普通 204-04 订阅不能只因共享 HPLMN 就套用 DITO 的
专用规则。明确匹配的既有 DITO 配置和相应离线回归仍保留；没有借此绕过许可证或授权。

每个域名分别查询系统 A／AAAA，一个地址族失败不会丢弃另一个；最多保留 16 个
可用单播地址。仅在标准 3GPP 域名的 DNS 无结果时尝试原有两／三位 MNC 拼写兼容，
不对任意手动域名猜造别名。默认不切换公共 DNS、不改 hosts 或系统路由。

直连逐地址尝试：无本地路径、初始 IKE UDP 超时等网络故障可继续。匹配的 IKE 响应
到达后固定该端点；同一初始请求的 NAT-D 提示在切换路径后可能保守触发 UDP 封装，
后续 AUTH 转录仍使用实际发送的初始字节。安装 SA 使用最终选中的真实端点。
SOCKS5 保留代理选路，不因目标失败退回直连；显式源地址约束不会在 UDP 中继或本地
4500 端口回退时被静默丢弃。

隧道建立前的跨域名回退仅接受 provider 明确标记的发现／预认证接入故障。开始 IKE_AUTH 后的
网络错误、原始 EAP-AKA 拒绝、证书／AUTH 错误和用户取消都不会被降级成普通 DNS 故障。
后续同卡身份计划增加了精确的“仅身份交换、无挑战”拒绝证明；这不是把任意 EAP 失败
改成接入故障，具体边界见下方同卡多身份一节。
本机取消会打断在等候的初始 UDP 读取，不等完重传间隔。
已验证隧道之后的 IMS 接入无响应采用独立的证明分类，见下方“IMS 无响应后的端点重建”，
不复用 DNS 故障标记，也不切换认证归属。

## 同卡多身份与成功优先（2026-10-26）

后续已将本阶段的身份交换／挑战、退避和清理状态边界反向补到
[Windows 实际回退路径](../../publish/windows-ike-retry-proof-20261026/README.md)。该 Windows
阶段只核对本端源码未变，不重跑 Linux 结果；不代表两端 COOKIE、退避计时等策略已全部一致。

本阶段全量、三轮关键／完整相关包 race、八种构建及独立复核已通过；证据和精确跳过项见
[阶段记录](../../publish/profile-identity-20261025/README.md)，不代表已部署或实卡通过。

EC20 主应用内部开启 `ReadProfileIdentities`，同时读取 AT 报告 IMSI 与 EF_IMSI；直接创建
严格适配器的旧调用默认不增加文件读取。读取前后核对两个来源和 ICCID，失败清除旧绑定。
EF_IMSI 使用独立长度、身份／奇偶位和 BCD 规则；只对明确不支持／缺失尝试一次备用路径，
传输、PIN／安全拒绝及畸形数据不能当成“没有第二个身份”。文件读数进入 Sensitive AT 边界。
EF_AD 只确定它对应身份的长度，另一个 IMSI 不继承该权威长度。

候选最多八个，均限当前已核验 ICCID。优先最近已注册成功的身份，再当前报告／文件读数，
最后其他历史；未读到的 IMSI 不按发现 PLMN、国家或品牌猜造。历史只有 IMSI 观察，旧身份
的归属长度按合法前缀重新构造；当前明确 EF_AD 优先，原有显式运营商配置保留。
每个身份独立生成 ePDG／MNC 计划，总上限仍为 64，为后面的身份及合法长度保留预算。

自动派生的 EAP NAI、SIP 身份使用选中的候选，既有显式运营商／SIP 配置仍按原规则处理。
硬件 AKA 则解析到原物理读卡身份，收到来电、短信、状态和 SIM 数据下载回调时也保留物理
来源。切换候选 IMSI 前重新检查原卡 AKA 就绪；读卡／鉴权前后核验不会被历史记录代替。

新增 `EPDGPreAKAIdentityError` 只来自实际 IKE provider：完整 EAP-Failure、此前仅有合法
身份交换、没有 AKA 挑战／格式错误／退避，且 DELETE 发送与本地 transport 关闭成功。
之前轮次的退避持续阻止此证明；即使挑战不完整或未调用硬件，也不能用之后的拒绝换身份。
已验证的最终 AUTH／隧道之后，只可按原有证明重建同认证归属端点，不能切换 IMSI。
这里不声称已经等到远端 DELETE ACK，亦不无限快速轮试。

身份历史独立存于 `vowifi.sim.identities.private.v1`：ICCID 摘要索引，最多 128 张卡，
每卡八个身份，文件 SQLite CAS 防止不同 Store 实例覆盖。只在实际 IMS Registered 后记
成功；可选历史写入失败不撤销注册，读历史失败时只使用当前已核验读数并提示告警。
私密文档包含完整 IMSI 与时间，不含原 ICCID 或 AKA 密钥；Sensitive 会隐藏公开导出，
但不是磁盘加密。请保护数据库，不要把它和诊断包提交到公共仓库。

当前新双来源读取仅覆盖 EC20；PC/SC／原生 QMI 可消费共同历史，但原生 QMI 读数不匹配
仍保守失败，未在本阶段实现双来源或多卡槽。Host IMS、WithSIM 开通、SIP 短信权限均不
因可选历史获得新的授权；完整读卡文件、运营商及多模组实测另行验收。

## 成功记忆和持久化

只有 IMS 确实 Registered 后才保存成功域名及认证归属。只记域名，不持久缓存 DNS IP，
下次重新解析。历史索引是 ICCID 与当前 IMSI 的联合 SHA-256，不跨卡或跨身份复用。
每卡配置用 ICCID 摘要索引，最多 128 份；成功历史保留最近 128 条。

数据库设置键为 `vowifi.epdg.discovery.private.v1`，标记 Sensitive，普通公开导出隐藏。
该 ePDG 设置的新条目不保存完整 ICCID、IMSI 或 AKA 数据；这不代表应用原有 SIM 数据库
不含身份。后续独立的私密身份历史为重建候选会保存完整 IMSI，见下节，不能混为一谈。
损坏的单条可选历史会被忽略，不改变有效的仅手动策略；损坏／未知版本的配置不会
被静默当成自动模式，需明确修复。成功记录写入失败不撤销已经成功的 IMS 注册。

管理员 API：`GET /api/devices/{id}/vowifi/discovery`，`PUT` 使用 GET 返回的 sim_token
及完整配置；响应 no-store。接口不发起 DNS、SIM APDU、重连、电话或短信。

## SIM 等价归属读取（2026-10-24）

EC20 适配器已修正 EF_EHPLMN 的文件编号为 `0x6FD9`／`28633`，即使 EF_AD 已提供
MNC 长度，也读取等价归属作为独立的 ePDG 发现候选。按卡内顺序去重，最多保留 16 条；
非法 BCD 数字不生成候选，只有第三位 MNC 的 `F` 表示两位 MNC。完整空列表不重复读；
默认长度读取失败时仅再试一次 12 字节读取，不循环重试或更改无线状态。

EF_AD 或有效显式归属优先；缺少长度时，只有唯一匹配当前 IMSI 前缀的等价归属能补足
长度，不能拿外国列表第一项替换鉴权归属。两位／三位同时匹配或缺少足够信息时，严格
适配器仍报告长度未知；应用已与下方的归属轮试编排配对启用，不把初始候选当作 EF_AD。
这个检查扫描全部已读记录，不能因为只保留 16 条发现候选而漏掉歧义。
附加 PLMN、当前驻网及发卡国家仍不改写 IMSI；已有显式运营商兼容配置保持不变。

读取结束后重新核对 IMSI 与 ICCID，发现卡／profile 变化即失败，不发布新身份或 AKA 绑定。
这是读取事务的前后核对，不保证检测到每次瞬时切换，也不代替后续 AKA 的卡片检查。
CRSM 解析校验状态字节范围；接受已完成的 `9000`／`91xx` 与原有 `9F00` 带数据兼容，
不把 `9001` 或待 GET RESPONSE 的 `9Fxx` 当作已完成文件。不会执行 proactive FETCH。

依据 [TS 31.102 4.2.18／4.2.84](https://www.etsi.org/deliver/etsi_ts/131100_131199/131102/19.04.00_60/ts_131102v190400p.pdf)
及 [ETSI TS 102 221 10.2.1.1](https://www.etsi.org/deliver/etsi_ts/102200_102299/102221/18.04.00_60/ts_102221v180400p.pdf)。
与 Windows 共享 [27 条解析向量](../../contracts/sim-home-plmn-v1.json)；软件证据与边界见
[阶段记录](../../publish/epdg-sim-plmn-20261024/README.md)。

## 未知 MNC 长度与成对轮试（2026-10-24）

EC20 应用入口默认启用归属感知编排，无需新配置项。EF_AD、唯一匹配的等价归属或既有
显式运营商规则能确定长度时，仍只有一个认证归属。否则 reader 明确标记长度未知，只
保留当前已核验 IMSI 的两位和三位 MNC 前缀；不创造新 IMSI、MCC 或额外 MNC 值。

每次尝试同时绑定 ePDG 和认证归属。标准域名可在上述合法前缀内辅助选择长度；外国
发现域名、驻网 PLMN、发卡国家及手动地址不能产生外国鉴权归属。固定地址也可有两种
合法长度组合，DNS 缓存或相同目的 IP 不应把它们误合并。总组合上限仍为 64。
各组合的发现列表独立，不因一个 provider 修改输入而污染下一次。

允许的预认证接入故障才尝试下一组合。代理按认证归属解析并在本次连接内缓存，代理
失败仍报错，不绕过代理直连；射频快照、关闭及 AKA 就绪检查不会因切换长度重复执行。
AKA／AUTH 失败、用户取消、隧道安全证据不足或 IMS 注册失败，不靠循环长度绕过。

选中的归属同时进入 EAP NAI、SIP 身份、运行状态和注册成功记忆。`home_mnc_uncertain`
表示卡片尚未给出确定长度，不因一次 DNS 成功改成“已读到 EF_AD”。只有 IMS 注册后才
记住“域名＋归属”，下次只在同 ICCID／IMSI 的合法范围内优先；后来读到明确 EF_AD 时，
不继续套用冲突的旧推断。成功历史仍不缓存 IP、不跨卡、不改写 IMSI 或绕过仅手动策略。

严格 EC20 API 默认仍拒绝无法确定长度；只有已经使用成对编排的应用入口内部开启
`AllowUnresolvedMNCLength`，不增加用户设置或提示。2026-10-25 后续已把 PC/SC 和原生 QMI
接入同一计划，具体读卡差异与软件边界见下节，不代表全部固件／卡槽已验收。

Windows 现有归属候选与 Go 共享 [8 条样例](../../contracts/ims-home-mnc-v1.json)。
实际 EAP／SIP 构造器、SQLite 重开、编排和软件验收边界见
[阶段记录](../../publish/epdg-mnc-plan-20261024/README.md)。

## PC/SC 与原生 QMI 归属证据（2026-10-25）

应用启动为两种 reader 内部启用成对轮试，不新增用户设置；严格构造器默认仍报长度未知。
PC/SC 同一读卡事务前后核对 ICCID／IMSI，验证成功后才发布本次绑定；AKA 前重新核对。
原来的 PIN required／剩余次数仍返回给管理层，失败不被伪装成可用的 VoWiFi 身份。
verified reader 对 EF_AD 单独区分缺失／短文件与传输、PIN 拒绝等致命错误；不沿用旧可选
元数据读取的吞错行为。原管理界面和严格 reader 的既有元数据读取方式保持兼容。

原生 QMI 不再使用依赖中“先选 OPL、否则默认两位”的辅助函数。OPL 与 PNN 合作提供
网络名称映射，并不是 IMSI 的归属证明，见 [TS 31.102 4.2.59](https://www.etsi.org/deliver/etsi_ts/131100_131199/131102/19.04.00_60/ts_131102v190400p.pdf#page=75)。
现在打开 USIM 逻辑通道，先读该通道的 EF_IMSI 与报告身份比较，再读取 EF_AD 第 4 字节；
不用驻网、OPL、品牌或默认长度冒充该证据。读取只包含 SELECT／READ／必要的 GET RESPONSE，
没有主动 VERIFY、UPDATE、AUTHENTICATE、FETCH、切卡或切射频。通道用独立有界取消域关闭。

缺失／短 EF_AD 或未知长度使用专门错误分类；不能通过 `errors.Join` 把清理错误、取消等
其他原因降级成可选文件缺失。只有完成当前身份核对，QMI 管理层才在此类错误下保留部分
身份；其他失败清空输出。reader 内部选用同一 IMSI 的合法前缀，AKA 前仍检查当前卡。
新的明确 EF_AD 与已选长度冲突时停止，不继续使用旧推断；既有显式运营商规则保留。

`WithSIM` 的开通／运营商地址流程没有端点／归属计划，因而拒绝临时长度；不会为“容错”
自动向按猜测生成的运营商域名发送身份。Host IMS 的原 SIM／ISIM 身份证明接口保持不变。

生产 QMI 方法已通过真实 UIM 客户端＋私有 Linux Unix socket 的合成线协议测试，未接触
实卡。当前逻辑通道仍使用物理 slot 1；不匹配的 USIM 会失败，不声称多卡槽自动选取已完成。

## IMS 无响应后的端点重建（2026-10-25）

真实 IMS provider 只有在没有匹配 SIP 响应、原因属于已识别的网络故障，并且废弃会话的
清理接口返回成功时，才签发 `IMSTransportError`。`100 Trying` 也计入响应；403／AKA／安全
协商／格式错误、用户取消和清理失败均不会变成“无响应”。未经标记的普通超时不能授权重建，
混合错误的每个分支都必须满足条件。原来的 SIP TCP／UDP 切换也保留相同响应边界。

编排器在关闭上一轮 IMS／隧道后，按域名＋认证归属排除已经失败的实际 IP。生产 IKE provider
把独立副本传到 transport，直连和 SOCKS5 都在拨号前过滤；IPv4-mapped 与 IPv6 文本按地址比较。
同域名地址用尽后尝试同认证归属的下一个域名，不修改系统 DNS 或落盘黑名单。

首个通过安全验证的隧道固定归属，一次 Enable 最多启动 16 次 IMS 注册；不是 16 个 SIP 包，
也不会因 IMS 无响应再轮试不同 MNC／IMSI。保留射频快照和关闭状态，不重复读取／切换射频。
provider 返回部分会话与错误时仍回收会话；旧监听器的取消域与代次检查隔离迟到失败。
各模组的排除集合、预算与代理缓存独立；仍只在 Registered 后保存成功记忆。

继续沿用现有状态灯和高级域名／IP 字段，不新增用户配置；`epdg_attempt` 仍是候选组合序号，
不是逐 IP 重建次数。软件验证、原始失败和未部署边界见
[阶段记录](../../publish/ims-gateway-retry-20261025/README.md)。
