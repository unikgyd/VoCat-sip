# 可选 SIP 内部通话（实验阶段）

本阶段实现独立 B2BUA 的双腿内部通话和服务器锚定 G.711 RTP。默认不连接运营商。
后续已加入单独授权的[可选 IMS 模组外呼](CARRIER_OUTGOING.md)，与内线权限分开；
没有接管现用 Asterisk，也不自动启用外线、AT 或 Host IMS。
注册成功只证明注册层可用，仍须实际软电话验证听感。

## 启用方式

1. 按 [SIP 分机服务](SIP_GATEWAY.md) 配置账号、监听地址与可信网段。
2. 开启「分机通话」，并为主叫和被叫分别开启账号下的「分机通话」，然后保存。
   所有新开关和旧配置迁移均默认关闭；通话与消息权限互不隐式开启。
3. 两端软电话使用同一服务的出站代理，启用 PCMA 或 PCMU，使用普通 UDP SIP 与
   RTP/AVP；被叫先注册。直接拨配置的分机号，不补国家码，不回落到模组或手机号码。
4. 同一被叫账号注册多个终端时共同振铃。第一份有效接听获选，其余分支取消；晚到
   的 2xx 仍 ACK 后 BYE。此处不是“所有不同账号自动群振”，运营商入呼另见
   [逐线路授权的多账号群振](CARRIER_INCOMING.md)。

Caller-ID 使用已认证账号及配置显示名，而不是客户端自报显示名。From／To 使用
统一身份域，默认 Realm；实际发送目的地始终是注册时观察到的 UDP 来源。域名不是
路由地址，也不能替代软电话的出站代理配置。Contact／Route／Record-Route 不得把
通话引向任意第三方地址；本阶段不支持多跳 SIP 代理的 Route Set。

## 通话与媒体生命周期

- 双腿独立 Call-ID、标签和事务；校验响应真实来源、Via 分支、Call-ID、CSeq、
  From／To URI 和标签，拒绝重复核心头及重复标签。BYE 还检查来源和递增 CSeq。
- CANCEL、ACK 与 BYE 来源检查发生在底层事务匹配前，避免伪造分支干扰合法端点。
  主叫取消先回复 CANCEL 200，再回复 INVITE 487，并立即停止外发 INVITE 重传。
- 尚未收到 1xx 时不抢发 CANCEL；保留有限迟到响应路径，收到 1xx 后才取消。
  2xx 重传再次 ACK，但不重复新开通话。首次有效接听以服务器端互斥选择为准。
- 接听后向主叫重传 200，直到有效 ACK 或默认 32 秒期限。被叫提前挂断仍保留
  主叫的 200／ACK 恢复路径；随后 BYE。双方任一端正常 BYE 都结束另一腿。
- 已接通的每条 SIP 对话独立每 30 秒发送一次无正文 OPTIONS，单次最多等 32 秒；
  校验原始 UDP 来源、Call-ID、双向标签、Via 分支与 CSeq。超时或原对话返回 408／481
  时结束这通通话，并通知另一腿或原运营商通话。两个探测互不推迟，正常静音不影响判断。
  OPTIONS／最终 BYE 共用递增的本地 CSeq，和远端请求的 CSeq 分开。其他最终响应仅确认
  原事务收到应答；不会跟随其 Contact、发送认证重试或把应答 SDP 用作媒体变更。
  普通挂断和退出会取消并回收探测；带标签的入站 OPTIONS 对不存在／结束的对话返回 481，
  错误来源／标签／序号在底层事务匹配前拒绝。此为原对话存活检查，尚未实现 RFC 4028 协商。
- 默认振铃期限 30 秒，迟到响应保留 32 秒；BYE／CANCEL 事务最多等待 3 秒。
  每个账号一次只参与一通通话，全局最多 16 通、512 个在途呼叫事务。
- RTP 使用本机路由对应的接口与临时 UDP 端口，服务器分别锚定两条媒体腿。
  只接受信令来源 IP 的有效 G.711 RTP；首次有效包学习实际来源端口，之后固定。
  SDP 中的第三方地址不作为外发目的地。两端 PCMA／PCMU 不同时做 8 kHz 单声道转码，
  保留序号、时间戳、SSRC 和 marker，去除不处理的 CSRC／扩展／padding。
- SDP 应答保留原 offer 的 m-line 顺序和数量，未接收媒体设端口 0。拒绝错误的静态
  PT、时钟、声道、重复映射及不支持的保持／加密媒体，而不是当作 μ-law 播放。
- 挂断先释放忙线状态和 RTP 套接字，迟到处理在后台有界保留。普通退出只做一次
  best-effort 终止，然后取消任务、关闭自己的资源，不等远端或模组恢复。

设置 API 返回 `calls` 中的主被叫、阶段、开始时间及双向转发包数，不含录音或 RTP
正文。状态页简化显示活动通话与状态灯；包数不证明双方听感。运行中每 15 秒更新，
可手动刷新。活动通话期间拒绝更改配置；显式关闭整个 SIP 服务则终止活动通话。

## 当前限制与验收范围

- 仅内部普通 G.711、单路 sendrecv RTP/AVP；已补 [RFC 4733 按键跨腿](SIP_DTMF.md)。
  [独立 RTCP](RTCP.md)、[SIP INFO DTMF](SIP_DTMF.md) 及 IMS 保持／恢复已另接入；
  内线尚无 AMR、保持 re-INVITE／UPDATE、转接、RFC 4028 Session Timer 协商、
  TCP／TLS、SRTP、ICE／TURN 或公网 SBC。
  不支持的 Require 扩展明确失败，不能靠客户端“注册成功”认定完整 PBX 可用。
- RTP 端口尚无固定范围配置；LAN／VPN 也必须允许服务器临时 UDP 媒体端口。
  仅映射 SIP 端口无法提供公网语音，当前版本不应直接暴露公网。
- Web 卡片管理 SIP 服务，不是通用 SIP 网页软电话。可选 IMS 外呼、入呼与现有
  网页首接仲裁已有独立合成验证；每模组完整模式隔离、Asterisk 和运营商短信仍需整合。
- 验证使用真实回环 UDP、独立 Digest 客户端与合成 SIP/RTP 终端。覆盖正常双向媒体、
  群振、取消、迟到接听、双方挂断、错误来源与标签、丢 ACK、超时及快速退出。
  Windows 主机和 Linux amd64 原生测试均运行。后续真实 Baresip 与 CT 纯 Host IMS 回拨
  已有[分阶段实测](VERIFICATION_20261028_SIP_FOLLOWUP.md)；该记录保留首次进程强杀后
  30 秒内未自动结束的失败。[新增原对话探测](VERIFICATION_20261028_SIP_DIALOG_LIVENESS.md)已完成
  统一软件检查、新旧构建的相同 80 秒对照及真实 Linux 内线强杀后的自动清理；真实外线
  分机故障和其他网络／重启组合仍需单独验收。
