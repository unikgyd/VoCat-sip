# IMS 通话生命周期加固

这是运营商 SIP 客户端的基础修复，不是已接通的分机—模组网关。
可选分机服务仍只有[内部通话](SIP_CALLS.md)；没有自动启用外线、切换模组模式、
拨打真实号码或修改 Asterisk。原 LICENSE 和授权检查保持不变。

## 已接入的行为

- 每个 `ims.Session` 独立准入一通电话。没有保持／混音能力时，第二通入呼返回 486，
  第二个本地主叫返回 `ErrCallBusy`；不会把另一台模组一起锁住。
- 本地挂断先结束可见通话、关闭 RTP，重复挂断不重复新开 BYE。
  未收到 1xx 时不发 CANCEL，停止 INVITE 重传；后续收到 1xx 才补 CANCEL。
  CANCEL 沿用原 INVITE 的 URI、Via 分支、From、To、CSeq 数字和 Route。
- 本地取消与运营商 200 竞争时，迟到的接通仍 ACK 后 BYE，不恢复 Active 或媒体。
  已接通响应的重传再次 ACK；不同 To 标签的额外接通分别清理，不替换获选对话。
  最多跟踪八个接通分支；超额分支仅做不分配新事务的 best-effort BYE。
- 初始 UDP INVITE 从 500 ms 退避至 4 s 重传；收到 1xx 或本地取消后停止。
  初始无响应期限 32 s，收到首个 1xx 后振铃期限两分钟，最终响应排空保留 32 s。
  取消后尚未得到最终响应时，仅该模组保留准入占用，避免立即再次发起不确定外呼。
- CANCEL／BYE 等 UDP 非 INVITE 事务重传同一报文，不创建新事务或新电话。
  挂断及后台清理事务最多等待五秒；运行时写操作连同等待写锁也有五秒上限，
  受调用方更短期限和取消约束。此范围不等于整个应用退出的耗时保证。
- 重复入呼 INVITE 重放原来的 180／最终响应，不换 RTP 套接字、不重复来电通知。
  并发接听只有一个调用者获准；另一个返回状态错误，不排队再接一次。
  200 写入结果不确定时不会交给第二个调用者重试，而是标记失败并尽力 BYE。
- 来电接听后的 200 在 UDP 上有界重传，直到匹配的 ACK 或 32 s。
  ACK 校验 Call-ID、对话 URI、标签及原 INVITE CSeq；延迟 offer 的 ACK 必须带
  可支持的 SDP answer。超时或不支持的 answer 结束媒体并尽力清理对话。
- 来电 CANCEL 校验原事务，先回复 CANCEL 200，再结束待决 INVITE；不能把已经
  发出的 200 或 486 改成另一个最终响应。BYE 检查对话标签与递增 CSeq，
  同一合法 BYE 重传可再次得到 200，错误标签或过期序号返回 481。
- 结束时间不被迟到事件重置，终态不复活；已关闭 RTP 不可重新配置为 Ready。
  每会话历史最多 128 条，不会提前删除仍有待决 INVITE 的记录。

## 验证与剩余范围

先独立复现六个失败用例，再修复；新增 25 个顶层生命周期测试，另有 UDP、
G.711／AMR、注册／续期、短信和分机网关旧回归。测试仅使用合成身份、模拟连接、
本机管道或 UDP 回环，Linux 不启用宿主主网络命名空间中的 XFRM/TUN 实验。
记录见工作区 `publish/vocat-call-lifecycle-20261023/`。

取消排空的工程思路与现有 C# 实现对照，Go 实现独立编写；本阶段没有修改或复制
VoSharp 的协议核心。两端完整互补目标不变，不把这些用例视作完整 RFC 或实网认证。

后续已接入[逐模组外呼授权／选线、持久化尝试防重和 PCM 桥](CARRIER_OUTGOING.md)，
仅做合成验收。后续又补上[运营商入呼多账号群振、网页与分机首接仲裁](CARRIER_INCOMING.md)。
Asterisk 可选中继及真实软电话／运营商验收仍未完成。
Host IMS 和模组 USB 音频后端也未补齐；默认静态发行版仍未启用原生 AMR。
IMS 的完整可靠临时响应／QoS、对话重协商和全方法严格身份校验仍需独立审查。

协议依据：[RFC 3261](https://www.rfc-editor.org/rfc/rfc3261.html) 与
