# 手机短信与 SIP MESSAGE 桥接

可选，默认关闭；不预置账号、模组、国家码、接收人或收费发送权限。当前已按设备选择
VoWiFi 或 [Host IMS](HOST_IMS_APPLICATION.md) 会话；这是短信业务接线，不是自动启动
Host IMS 或验证码 API，现用 Windows 程序没有自动替换。另可显式配置
[Asterisk 固定中继](ASTERISK_RELAY_PLAN.md)作为独立收发端，不要求它伪装成本地分机。

## 设置

在「SIP 分机服务」配置账号和可信内网／VPN，注册软电话。在模组线路中选择设备、
选线前缀、默认线路及可选国内号码补全，再打开「手机短信桥接」，分别授权收发。

| 配置 | 含义 |
| --- | --- |
| `sms_enabled` | 手机短信开关，独立于 `messages_enabled`、`calls_enabled` |
| 线路 `allow_sms_send` | 允许该模组线路承担收费发送 |
| 账号 `sms_send_lines` | 可使用的发送线路 ID，默认空 |
| 线路 `allow_sms_receive`／`sms_recipients` | 收件转发开关及最多 16 个接收分机 |

通话和短信共用选线规则，但授权独立。已知分机始终优先走内部消息，即使内部消息未开，
也不转为手机号。只有指定的精确国内位数才补国家码，短号不乱补。指定线路不可用不换卡。
内部消息关闭时手机短信仍可独立运行，SIP Allow 仍正确宣告 MESSAGE。

## 发件与防重

仅接入所选 VoWiFi／Host IMS 的已验证 SIM、已注册且 SMSReady 的会话，保留原地域／授权／设备策略。
不经 AT 回退、不启动注册、不改模式、不选择另一模组。真正提交时，在生命周期锁内
再次比较 IMSI＋ICCID，防止检查后切卡将短信交给另一张 SIM。所有入口继续共用原有
滚动小时发送限额，没有绕过开发版限额的新路径。

使用共享 `sip-sms-operation-v1` 契约：Realm、鉴权账号、精确 Call-ID 和规范十进制 CSeq
组成 SHA-256 操作 ID；网络地址、Via 分支及 LAN／VPN URI 域名不参与身份。
指纹另绑定模组、实际号码和正文，原会话回复还绑定原 SIM 哈希。

发送前先将「结果未知」写入私有持久化日志。24 小时内同一操作只回原结果，变更内容
返回冲突。超时、部分发送或关键窗口崩溃不自动重发。最多 2048 项尝试，损坏、容量满
或存储失败即阻止发送。实际文件 SQLite 使用整记录 CAS，独立进程／管理器不能覆盖
彼此的占位；每次尝试有随机 token，旧 worker 不能完成过期后重建的同 ID 尝试。
这仍不能宣称运营商层恰好一次；不能用复制数据库或清空日志来重试未知结果。
升级、存储及跨实例边界见 [短信持久化与接收身份](SIP_SMS_DURABILITY.md)。

202 只表示全部分段被传输层接受，不代表手机收到或用户已读；有真实投递确认才可
返回 200。部分接受／不确定返回 504 和 `X-VoCat-Delivery: unknown`，不新建业务请求
自动重试。正文与结果进入正常发件历史，历史写失败也不能触发重新提交。
导出业务日志只记操作哈希、模组、分段计数，不记正文、IMSI 或 ICCID。

同一 Manager 生命周期内，每模组同时最多一个网关发件；其他模组独立。
换 SIP 监听器不清掉仍在执行的模组隔离锁；这不是不同操作的跨进程全局模组互斥锁。
底层不响应取消也不会让 SIP 退出一直等待；任务最终回来后只记录结果，不追加发送。

## 收件队列与回复

schema 29 在真实收件的同一个 SQLite 写事务中保存 Inbox、独立来源收据及原收件计划；
提交后才唤醒投递，不再按之后轮询时的新配置捕获收件人。实时拼接短信只在完整、
可解码时捕获一次逻辑计划。重启保留原已入队消息；关闭功能、没有接收授权、历史同步
或转发容量不足时保留 Inbox 和空来源保护，在来源保护期内，之后开启、加账号或释放
容量不补发该来源。
完整规则与 AT 存储观察的保守降级见[接收入库与原计划](SIP_SMS_RECEIVE.md)。

最多 256 条逻辑短信，每条 16 个接收分机，保留 24 小时。原始收件箱不受队列过期影响。
离线且从未交给 SIP 传输的消息等待注册，不阻塞在线分机。每批至多 16 个收件人并发，
每分机一次一批；同分机最多八个 Contact 来源并发，同来源别名去重，仅使用实际观察到
的 UDP 地址，不信任 Contact 指向任意主机。
固定 peer 在认领前做不带正文／SIM 身份／认证凭据的 OPTIONS，失败保留原 Queued 与期限。
每个运行实例单 owner／一秒探测及一秒短缓存，本地分机优先、固定端点仅一个投递 worker。
成功探测不代替当前持久权限及 Inbox 检查；探测到认证／重传共用原总预算。
完整边界见[固定 peer 离线探测](SIP_SMS_RECEIVE.md#固定-peer-的离线探测)。

发出前先持久化未知结果，至少一个 Contact 的全部分段匹配到 2xx 才记该分机接受，
不为之后上线的另一台同账号设备补发；这不是所有终端离线历史同步。
网络结果未知不自动再投递，原文仍在正常收件箱可核查。新建或重设凭据的同名分机
不能继承旧账号待收的私密短信。接收身份使用私有随机代际；同密码重新填写、删除重建、
显式重置均更新代际，普通保存／停用／启动则保留。真实 Manager 的收费准入、收件 claim
及每次 MT MESSAGE 初发／重传／认证重新读取持久授权，旧 runtime 不能仅凭旧内存配置继续发包。

真实应用计划绑定实际 Inbox 行及内容指纹。claim 与 Inbox 检查同事务，每次 MT UDP 发包
前以同一个只读快照核对 Settings／Ledger／实际 Inbox：删除或修改原文的待投消息不会
发旧拷贝，仅标记已读不影响投递。独立来源
收据在 Inbox 删除后仍保留二十四小时的有界保护。库 API `QueueSMS` 的显式
`SourceIndependent` 事件没有实际 Inbox guard，不能混同应用收件入口。
MT 使用独立有界 UDP 事务覆盖超时重传，普通分机 MESSAGE／REGISTER／通话路径不变。
国内格式原发件人的 canonical 回复号码在首次准入时冻结，不因后来改国家码而重解释；
旧日志国内号码保守只读。实现与验证边界见[接收规则](SIP_SMS_RECEIVE.md)。

From 使用 `sms2-<设备摘要>-<原卡摘要>-<国际号码>@统一身份域`，显示名仍为来信号码。
user-part 最长 78 个 ASCII 字节，卡摘要保留完整 SHA-256，避开已观察的 Asterisk
79 字符字段边界。完整旧 `sms.<模组编码>.<SIM哈希>.<号码>` 格式仍可兼容，但恰为
79 字符的旧地址保守拒绝；新旧格式
残缺／非法或设备匹配不唯一均拒绝，不转普通号码或默认线路。格式校验不能保证识别
所有号码尾部截短，尤其截短后仍是合法号码的情况，不能声称具备任意截断检测。

回复定位原模组及原卡，默认线路变更不改原目标，换卡时拒绝。未知卡或非电话号码来源
使用只读标识，不把银行字母发件人、短码变为收费目标。权限仍绑定原模组线路及原卡。
软电话仍须把出站代理指向同一 SIP 服务，统一身份域不能替代客户端的实际网络路由。

## 边界

当前限可信内网／VPN、UDP、UTF-8 `text/plain`，不含 CPIM、HTML、群聊、公网 SBC 或 TLS。
仍遵守 [RFC 3428 的 UDP 边界](https://www.rfc-editor.org/rfc/rfc3428.html#section-8)：
外发 MESSAGE 整包不超过 1300 字节，绝不截断冒充成功。MT 原文最多 16,384 个 UTF-16
单元，严格 UTF-8、非空且无 NUL；按 Unicode scalar 边界分成至多 280 个 UTF-8
原文字节的块，多块加 `[i/n] `，前缀及认证仍计入整包限制。每个 Contact 顺序收齐
全段才算成功，部分接受后失败保持 Unknown，不续发、不合并不同 Contact 的部分副本。
详细限制见[接收分段边界](SIP_SMS_RECEIVE.md#仍有的传输边界)及
[共享样例](../../contracts/sip-message-parts-v1.json)。
普通分机 MESSAGE／运营商 MO 仍限 4,096 字节。不支持内容不阻塞后续收件；
任意长度、TCP、软电话透明重组和真实长消息互通不因此获得保证。

待转发正文存在标为 Sensitive 的私有队列，与正常收件箱一样依赖数据库文件保护，
不是磁盘加密。关闭功能暂停投递，已入队且未过期的消息在重新开启后可继续。
设置页只显示统计，不展示验证码正文；未加密 SIP 端口请勿直接开放公网。
