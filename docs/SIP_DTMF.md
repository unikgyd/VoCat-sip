# SIP 通话按键

网关协商 `telephone-event/8000`（RFC 4733），接通后支持分机／固定 peer 之间的按键，
以及 SIP 和原运营商通话之间的按键传递。不开新通话、不换卡、不改变默认路由。

## 协商与转发

每条 SIP 腿独立解析所选 audio block，事件使用动态载荷号和 0–15 数字集合。错误或重复
fmtp 只关闭可选事件，不把普通 G.711 语音拒绝掉。多个媒体块不能互相覆盖协商。
网关主动 offer 使用 PT 101；对应 answer 不能擅自换为未提供的事件载荷号。

分机／peer 之间取双方数字集合的交集，按接收方载荷号重写 RTP PT；保留原事件时间戳、
SSRC、序号、marker、duration 和冗余结束报告。接收方 SDP 的连接地址不代替信令来源 IP，
事件必须来自原已配置／已学习的媒体端口；事件本身不能抢占首次合法语音的对称 RTP 端口。

SIP→运营商仅将一次完成事件提交给绑定的设备 ID＋原 Call-ID。三份结束报告去重，
不自动重发失败或未知的动作。一个动作在途时丢弃后续按键，不能积压到另一通电话。
提交在独立 worker 中限时执行，不阻塞 PCM 读取。SIP 挂断、来源失效或关闭取消在途提交。

IMS→SIP 从同一 active RTP 媒体的 `ReadDTMF` 消费完成事件；接管时清除振铃期间的旧键，
超过 320 ms 的积压事件不重放。网关用 SIP 腿协商的 PT 生成 160 ms 事件、20 ms 更新和
三份结束报告，和该腿 PCM 共用 SSRC 与序号；发送事件期间丢弃旧语音，恢复时推进时间戳。
媒体协商版本变化时停止原事件，不把剩余报告发给新端点。

显式 USB 模组仅将 SIP 按键交给原租约 `AT+VTS`；新动作前仍检查原 SIM、USB 代次和
CLCC。没有从 UAC PCM 自动识别 DTMF 的实现，反向来音按普通语音传递。

## 权限、首接与边界

本次沿用既有逐线／分机／peer 权限和会话来源校验，只有群振获胜腿连接运营商媒体。
迟到 200 的败选腿、已结束的 RTP socket、另一模组的事件不能取得该通话的控制权。
DTMF 数字不写入持久日志，避免记录 IVR PIN。操作提交不等于运营商确认收到按键。

RTP 事件本身不包含带内双音检测、RTCP、转接、SRTP 或公网 SBC。未协商或对端不支持时
不猜测其他传输方式；新增的 INFO 兼容入口见下节，高级能力仍列在
[并集清单](FEATURE_UNION.md)。

## INFO 兼容入口（新增源码，待统一验证）

分机／固定 peer 的已建立运营商通话可接收 legacy INFO `application/dtmf-relay`。必须匹配
原来源端点、Call-ID、双向标签、URI 身份和递增 CSeq；群振只有已获首接的那条腿可提交。
Info Package 模式返回 469，未知内容类型返回 415，不按原始文本猜测按键。

正文最多 256 字节，要求一个 `Signal`（0–9、*、#、A–D）；可选 `Duration` 只允许
40–5000 的十进制毫秒值。实际运营商动作沿用原有固定 160 ms RTP 事件／模组 VTS 能力，
不会把任意时长传给设备。重复字段、额外字段、控制字符和畸形数字拒绝。

同一事务的正文指纹和结果保留在有界对话缓存中。重复请求不会再次产生运营商按键，
冲突重放拒绝；按键在途时返回 491，不排队。只有原通话动作成功才返回 200，失败／未知
保留结果，不自动换传输重发。操作在独立、受通话关闭取消的两秒 worker 中执行。
此兼容路径用于 SIP 到已绑定运营商腿，不新增分机间 INFO 文本转发或运营商 INFO 兜底。

依据：[RFC 6086 的 legacy INFO 模式](https://www.rfc-editor.org/rfc/rfc6086.html#section-3)。
本节源码按先实现、最后统一测试的要求接入，尚未用最新完整源码执行验证；下方历史 RTP
测试结果不能代替本节验收。

软件测试包含真实 IMS 会话、网关及 UDP／RTP 端点，分机双向 PT 转换，peer Digest
重试、两模组并行和群振首接；SIM／隧道／运营商由本地合成端模拟。没有发起实际运营商
通话或修改现有 Asterisk 服务。真实 IVR 和软电话联合验收仍待完成。

依据：[RFC 4733](https://www.rfc-editor.org/rfc/rfc4733)。
